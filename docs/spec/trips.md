# Trips Spec

## 목적

여행 계획은 두 사람이 같이 가는 여행 하나를 한곳에서 준비하고 기록하는 공간이다. 기간, 숙소, 이동(항공/기차 등), 준비물, 날짜별 계획을 한 화면에서 다룬다. 여행이 끝난 뒤에도 무엇을 했는지 남는 기록이어야 한다.

`만나는 날`(meetings)은 하루 단위 약속을 맞추는 기능이고, 여행 계획은 여러 날이 이어지는 하나의 여행을 다룬다. 두 기능은 서로를 대체하지 않는다.

## 진입

- 하단 navigation tab을 추가하지 않는다.
- 다가오거나 진행 중인 여행이 있으면 Home에 `다가오는 여행` 카드를 보여준다. 남은 날과 준비물 진행을 함께 보여주고 누르면 여행 계획으로 간다. 해당하는 여행이 없으면 카드를 아예 보여주지 않아 홈이 길어지지 않게 한다.
- Home menu의 `기능 모아보기`에 `여행 계획` 항목을 제공한다.
- 여행 계획 화면은 bottom-tab root가 아닌 sub-screen이며 back action을 가진다.

## 여행

- 여행은 제목, 목적지, 시작일, 종료일을 가진다.
- 기간은 시작일과 종료일에서 계산한다. 같은 날이면 `당일`, 아니면 `N박 M일`로 보여준다. 사용자가 박/일 수를 따로 입력하지 않는다.
- 종료일은 시작일보다 앞설 수 없다. 어기면 저장하지 않고 입력값을 유지한 채 안내를 보여준다.
- 여행은 `계획 중`, `다녀옴` 두 상태를 가진다. 상태는 사용자가 직접 바꾼다. 날짜가 지났다고 자동으로 바뀌지 않는다.
- 날짜가 지났는데 아직 `계획 중`이면 상세 위에 옮길지 물어본다. 일정이 밀렸을 수도 있어 자동으로 바꾸지는 않는다.
- 두 member 모두 여행을 만들고 편집할 수 있다. 마지막으로 저장한 사람은 `updatedByProfileId`로 기록한다.
- 여행 삭제는 만든 사람만 할 수 있다.

## 여행 항목

여행 하나에 붙는 항목은 종류로 구분한다.

- `숙소`: 묵을 곳. 이름, 메모, 체크인 날짜/시각, 체크아웃 날짜/시각. 하루가 아니라 **날짜 범위**를 가진다.
- `이동`: 이름(편명이나 노선), 메모, 이동 수단, 출발지/도착지, 출발 시각, 도착 시각.
- `준비물`: 챙길 것. 이름과 메모. 체크 상태를 가진다.
- `계획`: 날짜별로 무엇을 할지. 이름, 메모, 선택적 날짜와 시각.

- 항목은 여행 기간 안의 날짜만 가질 수 있다. 날짜가 없는 항목은 `날짜 미정` 묶음에 둔다.
- 날짜를 정한 항목에는 `09:30` 형태의 시각을 선택적으로 붙일 수 있다. 형식이 맞지 않으면 저장하지 않는다.
- 날짜가 없으면 시각도 없다. 기간이 줄어 날짜가 미정으로 돌아가면 시각도 함께 지운다. 체크인은 남고 체크아웃만 기간 밖이면 체크아웃만 비운다.
- 숙소 체크아웃은 체크인 다음 날부터만 고를 수 있다. 같은 날이나 이전 날은 저장하지 않는다.
- 이동 수단은 비행기, 기차, 버스, 자동차, 배, 도보 중 하나이며 기본값은 비행기다. 이동이 아닌 종류에는 수단과 출발지/도착지를 저장하지 않는다.
- 도착 시각만 있고 출발 시각이 없으면 저장하지 않는다.
- `준비물`만 체크 상태를 쓴다. 다른 종류는 체크 UI를 보여주지 않는다.
- 항목은 두 member 모두 추가/수정/체크할 수 있고, 삭제는 만든 사람만 할 수 있다.

## 화면 구조

- 여행 목록: `계획 중`과 `다녀옴`을 나눠 보여준다. 여행이 없으면 낮은 압박 empty state를 보여준다.
  - 맨 위에 `새 여행 만들기` 줄을 두고, 누르면 여행 sheet가 올라온다.
  - `계획 중`은 가까운 날짜부터, `다녀옴`은 최근에 다녀온 것부터 보여준다.
  - 여행 카드는 담아둔 사진 중 가장 최근 것을 표지로 쓴다. 사진이 없으면 단색 표지를 쓴다.
  - 표지에는 오늘 기준 위치(`D-12`, `여행 2일차`, `다녀온 여행`)와 제목, 목적지·기간을 얹는다.
  - 카드 아래에는 계획/준비물/사진 개수를 조용히 보여준다.
  - 카드 전체가 누르는 영역이다. 별도 열기 버튼을 두지 않는다.
- 여행 상세 위쪽에는 기간과 상태를 두고, `여행 정보 고치기`/`여행 지우기`는 `...` 하나로 모아 sheet에서 고른다. 맨몸 text로 늘어놓으면 눌러야 하는 것인지 읽히지 않는다.
- 여행 상세는 tab 네 개다. `일정`, `숙소`, `준비물`, `사진`.
  - 종류마다 tab을 두면 여섯 칸이 되어 390px에서 가로로 밀린다. 시간 흐름은 `일정` 하나로 모으고 성격이 다른 것만 따로 둔다.
  - 이동과 계획은 `일정` 안에서만 다룬다.
- `일정` tab이 기본이며 읽기 중심 타임라인이다.
  - 여행의 모든 날을 `1일차 · 9월 12일 (토)` 형태 header로 이어 보여준다. 항목이 없는 날도 자리를 남긴다.
  - 하루 안에서는 시각순으로 놓고, 시간 미정 항목은 그날 끝에 붙인다.
  - **숙소는 시각 항목으로 끼우지 않는다.** 하룻밤을 통째로 차지하는 것이라 다른 일정 사이에 끼면 어색하다. 대신 하루 머리에 머무는 곳 띠로 보여준다.
    - 체크인 날은 `체크인`과 체크인 시각, 이어지는 밤은 `머무는 곳`과 박 수, 체크아웃 날은 `체크아웃`과 체크아웃 시각으로 읽힌다.
    - 체크아웃 당일 밤은 더 이상 머무는 밤이 아니다.
  - 이동은 `08:20 → 09:35`처럼 구간으로 보여주고, 수단 icon과 `김포공항 → 제주공항` 경로 한 줄을 함께 둔다.
  - 장소를 붙인 항목은 분류 icon과 장소 이름, 주소를 한 줄 더 보여준다.
  - 준비물은 시간 흐름이 아니므로 타임라인에 넣지 않는다.
  - 날짜 미정 항목은 `언제든` 묶음으로 마지막에 둔다.
  - 여행 기간 중이면 오늘 날짜 header에 `오늘` 표시를 붙인다.
  - 그날로 묶어둔 사진은 하루 끝에 가로로 이어 보여준다. 누르면 전체 화면 뷰어가 열린다.
  - 같은 날 항목은 끌어서 순서를 바꿀 수 있다. 시각이 같으면 시각만으로 순서를 정할 수 없어서다. 옮긴 순서는 저장한다.
  - 항목을 누르면 그 자리에서 고치는 sheet가 열린다.
- `숙소`와 `준비물` tab은 목록이다. 날짜 흐름보다 목록으로 읽는 편이 자연스럽다.
  - 준비물 tab은 체크한 항목 수를 `3 / 8`처럼 조용히 보여준다. 퍼센트, 점수, 달성률 copy를 쓰지 않는다.
  - 준비물은 담당을 고를 수 있다. `영우`, `민영`, `함께` 세 가지다. 둘 다 챙겨야 하는 것이 있어서 `함께`를 따로 둔다. 정하지 않아도 되고, 같은 값을 다시 누르면 담당이 풀린다. 이 세 가지가 아닌 값은 담당이 될 수 없다.

## 입력 방식

- **입력은 모두 bottom sheet로 연다.** 폼을 목록 위에 늘 펼쳐두면 읽을 자리를 뺏고 화면이 양식처럼 보인다. 만들 때만 올라오고 저장하면 닫힌다.
- 항목을 담을 때는 먼저 종류를 고르고, 고른 종류에 맞는 칸만 보여준다. 종류마다 물어봐야 하는 것이 다르다.
- 날짜와 시각은 직접 타이핑하지 않는다. `2026-09-12`나 `09:30`을 손으로 적게 하면 형식을 틀리기 쉽고 앱처럼 느껴지지 않는다.
- 여행 날짜는 달력 sheet에서 고른다. 돌아오는 날은 떠나는 날 이전을 고를 수 없게 막고, 고른 기간을 저장 전에 `2박 3일`로 되짚어준다.
- 떠나는 날을 바꿔 돌아오는 날이 그보다 앞서게 되면 돌아오는 날을 비운다.
- 시각은 시/분 sheet에서 고른다. 분은 5분 단위이며, 밖에서 들어온 값이 단위에 어긋나면 가장 가까운 칸으로 맞춘다.
- 시각 sheet는 늘 `00`부터가 아니라 현재 값 근처에서 열린다.
- 값을 고르지 않은 자리는 `날짜 고르기`, `시각 고르기`처럼 다음 행동을 그대로 적어 보여준다.
- sheet는 키보드가 올라와도 입력 칸이 가리지 않게 keyboard inset만큼 밀어 올린다.
- 저장에 실패하면 sheet를 닫지 않고 입력값을 유지한 채 안내를 보여준다.

## 손가락 기준 UI

- 이 앱은 web으로 배포하지만 휴대폰에서 손가락으로 쓴다. hover에 기대는 표현을 쓰지 않는다.
- 누르는 요소는 44px 이상으로 잡는다. tab 줄, 아이콘 button, sheet 안의 선택지 모두 해당한다.
- tooltip을 유일한 설명으로 쓰지 않는다. 마우스가 없으면 보이지 않는다.
- 되돌릴 수 없는 동작(여행 삭제, 항목 삭제)은 확인 sheet를 거친다. 아이콘 한 번으로 사라지지 않는다.

## 사진

- `사진` tab에서 단말기 갤러리의 사진을 담을 수 있다.
- Spark plan에는 Cloud Storage를 쓰지 않는다. 앱이 긴 변 1280px까지 줄이고 품질을 낮춰 data URI로 만든 뒤 `tripPhotos/{photoId}` 문서 하나에 담는다.
- data URI 길이는 `kTripPhotoMaxDataUrlLength`를 넘길 수 없다. UI 상한과 `firestore.rules` 상한은 같은 값을 쓴다.
- `data:image/`로 시작하지 않는 값은 저장하지 않는다.
- 사진은 두 member 모두 볼 수 있고, 지우거나 설명·날짜를 고치는 건 올린 사람만 할 수 있다.
- 사진은 여행 기간 안의 날짜로 묶을 수 있다. 묶은 사진은 사진 tab에서 날짜로 좁혀 보고, 일정 tab의 그날 끝에도 함께 보인다.
- 갤러리를 열 수 없는 환경에서는 담기 action을 비활성화하고 안내 문구로 바꾼다.
- 설명은 `kTripPhotoMaxCaptionLength`(200자)까지다. UI, controller, `firestore.rules`가 같은 값을 쓴다.

### 배치와 보기

- 담기 action은 한 줄로 줄이고 남는 자리를 사진에 내준다.
- 가장 최근 사진을 4:3으로 넓게 두고 나머지를 두 칸 정사각으로 이어 붙인다. 같은 크기 조각만 늘어놓으면 앨범이 아니라 목록으로 읽힌다.
- 설명은 조각 높이를 흔들지 않도록 사진 위 gradient에 얹는다.
- 내가 담은 사진에는 조각 위에 조용한 표시를 둔다.
- 조각을 누르면 화면 가득 뷰어를 연다.
  - 좌우로 넘겨 다른 사진을 보고, 현재 위치를 `2 / 7`로 보여준다.
  - 손가락으로 확대하고 두 번 눌러 확대/원래 크기를 오간다.
  - **확대하지 않은 동안에는 사진 pan을 꺼 둔다.** 켜 두면 넘기려는 손짓을 사진이 먼저 먹어 다음 장으로 넘어가지 않는다. 확대한 동안에는 반대로 넘기기를 잠근다.
  - 올린 사람은 뷰어에서 설명을 바로 붙이거나 고친다.
  - 마지막 한 장을 지우면 뷰어를 닫는다.

## 데이터 규칙

- 여행은 `trips/{tripId}`에 저장한다.
- 항목은 `tripItems/{itemId}`에 저장하고 `tripId`로 여행을 가리킨다. 시각은 `timeLabel`, 종료 시각은 `endTimeLabel` 문자열로 저장하고 비어 있으면 미정이다.
- 숙소 체크아웃 날짜는 `endDateKey`, 이동 정보는 `transportMode`, `fromLabel`, `toLabel`에 저장한다. 해당 종류가 아니면 빈 값으로 둔다.
- 사진은 `tripPhotos/{photoId}`에 저장한다. 사진 저장과 삭제는 각각 문서 하나만 쓴다.
- draft 입력, tab 전환, 목록 스크롤, 상세 열기는 Firestore write를 만들지 않는다.
- 여행 저장은 `trips/{tripId}` 한 문서만 쓴다.
- 항목 저장, 체크 토글은 각각 `tripItems/{itemId}` 한 문서만 쓴다.
- 여행을 삭제해도 항목 문서를 batch로 지우지 않는다. 화면은 남은 항목을 여행 없는 것으로 보고 숨긴다.

## Copy Guardrail

- 여행 copy는 재촉하지 않는다. `아직 안 정했어요`, `필요할 때 채우면 돼요` 같은 낮은 압박 표현을 쓴다.
- 준비물 체크는 진행률 압박이 아니라 기억을 돕는 장치다. `달성률`, `완료율`, `점수` 표현을 쓰지 않는다.

## Empty/Failure State

- 여행이 없으면 `아직 계획한 여행이 없어요` 계열 copy와 `여행 만들기` action을 보여준다.
- 항목이 없는 tab은 그 종류에 맞는 짧은 안내를 보여준다.
- 저장 실패 시 입력값을 유지하고 다시 시도할 수 있게 한다.

## 수용 기준

- 시작일과 종료일로 계산한 기간 표기가 `당일`, `1박 2일`, `2박 3일`처럼 정확해야 한다.
- 종료일이 시작일보다 앞선 입력은 저장되지 않는다.
- 준비물 체크 토글이 다른 종류 항목에는 나타나지 않는다.
- 여행 기간 밖 날짜는 항목에 설정되지 않는다.
- 타임라인은 하루 안에서 이른 시각이 위에 오고, 시간 미정 항목이 그 뒤에 온다.
- 타임라인에서 항목을 눌러 고쳐도 새 항목이 생기지 않고 원래 항목이 갱신된다.
- 숙소는 타임라인 시각 항목으로 나타나지 않고, 체크인부터 체크아웃 전날 밤까지 머무는 곳 띠로 나타난다.
- 이동은 수단, 출발지/도착지, 출발/도착 시각을 잃지 않고 저장된다.
- 사진은 크기 상한 안의 data URI만 저장되고, 올린 사람에게만 삭제 action이 보인다.
